The Cloud-to-Edge Continuum & OCI Image Registries

  • Modern Deployment Paradigms: Shift from static, environment-dependent configuration to packed, immutable containerized shipping (Docker, Kubernetes).
  • The Role of Registries: Container image registries have evolved from passive, out-of-line storage bins into critical, runtime-active middleware components.
  • The Geodistributed Bottleneck: Multi-region orchestration introduces severe performance challenges, governed by physical network propagation delays (RTT), Bandwidth-Delay Product (BDP) limits, and transactional consensus barriers (CAP).

Architectural Trade-offs: Transactional ACID vs. Elastic BASE

  • Stateless Registry (ACID-oriented): Direct, POSIX-compliant writes to local block storage (Registry:2 on Local SSD). Prioritizes immediate strong consistency, transactional safety, and low single-user latency, but remains highly vulnerable to "data gravity" bottlenecks under high concurrent access.
  • Stateful Registry (BASE-oriented): Complex microservice ecosystem (Harbor on S3 Spaces) coupling a relational control plane (PostgreSQL/Redis) with decoupled cloud object storage. Embraces eventual consistency and L7 redirects to enable horizontal, geographical elasticity.
  • The Core Question: How does L7 Control Plane complexity (Statefulness) impact runtime performance and resource efficiency when compared to physical, Layer 4 transport-layer constraints?

Control Plane vs. Data Plane: Schematic Comparison

  • Registry:2 Unified Network Path:
    • Operates via Synchronous L7 Proxying. NGINX actively intercepts, terminates TLS, parses, and proxies all control traffic (manifests) and heavy data traffic (payload layers) directly to the local SSD persistence layer.
    • The reverse proxy and the registry engine share the critical path, making the host highly susceptible to local I/O queue starvation under concurrency.
  • Harbor Decoupled Datapath:
    • Employs L7 Data Plane Offloading. The L7 Control Plane (Harbor Core) validates client credentials against PostgreSQL, then instantly offloads the heavy binary I/O stream to S3 Object Storage via HTTP 307 Temporary Redirects.
    • Bypasses the NGINX reverse proxy entirely during the binary streaming phase, protecting the host core from network bufferbloat.
  • The "Sidecar Tax" Hypothesis: Stateful, multi-container synchronization (PostgreSQL, Redis, Core) is predicted to introduce a measurable latency and CPU coordination overhead (T0(N)) during metadata-heavy operations.

L7 Metadata Control Plane: Quantifying the "Sidecar Tax"

  • Formal Efficiency Model (Amdahl's Law):
    We formalize the middleware tax using the distributed systems efficiency model:
    EP = 1 / (1 + T0(N) / T1(N))
    where T1(N) represents useful execution work, and T0(N) represents the non-parallelizable coordination and synchronization overhead.
  • Registry:2 Efficiency (T0 ≈ 0):
    Achieves a median metadata latency of 22.08 ms. Since the stateless engine avoids relational database and loopback overhead, the coordination tax is virtually non-existent, pushing efficiency near-ideal (EP ≈ 1) and operating close to the physical WAN RTT floor.
  • Harbor Stateful Penalty (The 'Sidecar Tax'):
    Median metadata latency jumps to 80.56 ms. Serving the same L7 GET Manifest request requires an additional ~58 ms of compute time spent in PostgreSQL transaction validation, Redis session cache lookup, and OIDC authorization.
  • Tail Latency & Outliers:
    High-concurrency metadata stress (500 VUs) triggers PostgreSQL Connection Pool Starvation, driving queuing delays exponentially up to the 30s SLA limit.

Control Plane Saturation & Right-Censoring Mitigation

  • PostgreSQL Connection Starvation:
    Sustained peak metadata concurrency (500 VUs) saturates Harbor's multi-container control plane, quickly depleting the database connection pool and driving queuing delays (Tq) exponentially.
  • Systematic SLA Breaches:
    Cumulative queue delay rapidly exceeds the 30-second application threshold, forcing the k6 load generator to drop active TCP connections and record HTTP gateway timeouts.
  • Right-Censoring Mitigation:
    To prevent optimistic bias (where 30s timeouts artificially compress mean latencies), uncompleted samples are mathematically isolated, preserving the true asymptotic scale of the control-plane collapse.
  • Self-Induced Thrashing Cycle:
    Sudden queue truncation from timeouts temporarily relieves database pressure (dropping CPU and throughput), only to re-saturate upon client reconnection in a destructive, cyclical collapse.

L7 Data Plane: Throughput Scalability (1 - 100 VUs)

  • Linear Scaling Zone (≤ 40 VUs):
    Both Registry:2 and Harbor scale identically and linearly, climbing up to ~150 MiB/s. This empirical overlap demonstrates the complete success of Harbor's Datapath Decoupling strategy: under moderate load, the stateful control plane does not penalize binary payload operations.
  • Physical Saturation Plateau (> 40 VUs):
    Beyond 40 VUs, the throughput curves flatten, converging and fluctuating within a narrow band of 200–240 MiB/s. The expansion of variance bands (shaded regions) flags the onset of physical WAN congestion, transport packet loss, and buffer jitter.

Payload Breaking Point: BASE Offloading vs. ACID Data Gravity

  • The Local SSD Bottleneck (ACID Data Gravity):
    Under a maximum concurrency of 500 VUs, Registry:2 (writing directly to local SSD) suffers from severe write-queue starvation on the host's storage controller. The POSIX-compliant synchronous ACID path creates an I/O bottleneck, driving average write latencies up to 10 seconds and triggering systematic 30-second timeouts.
  • Harbor S3 Offloading Stability (BASE Paradigm):
    Harbor utilizes L7 Data Plane Offloading via HTTP 307 Redirects. Once the client is authenticated, Harbor completely delegates the binary data stream directly to DigitalOcean Spaces (S3 Object Storage).
  • Stabilized Response Times:
    By bypassing the host proxy and disk bottlenecks entirely, Harbor's payload write latencies stabilize on a flat, compact plateau between 4 and 6 seconds, with zero cascading queue failures or systematic SLA timeouts.
  • Architectural Outcome:
    Highly parallel, eventually consistent distributed storage (BASE) successfully bypasses core host I/O constraints, demonstrating superior scalability for data planes in the geodistributed Cloud Continuum.
Fig. 8: Heavy payload breaking point: Latency evolution under 500 VUs. S3 offloading (BASE) prevents the local host write-queue starvation suffered by Registry:2 (ACID).

L4 Transport Layer Limits: Cumulative BDP Analysis

  • The Bandwidth-Delay Product (BDP) Model:
    The fundamental data capacity of a network pipe is governed by transport physics:
    BDP = Capacity × RTT
  • Single-Socket Throughput Boundary:
    For any individual unconstrained TCP connection, the maximum achievable throughput is bounded by the receive window size (Wmax) and the Round-Trip Time (RTT):
    Throughputmax ≤ Wmax / RTT
  • Constrained Buffer Regime:
    By forcing the kernel TCP window to a fixed Wmax = 64 KB over our geodistributed WAN link (RTT ≈ 16 ms), the single-socket ceiling is strictly capped at:
    Throughputmax ≤ 64 KB / 16 ms ≈ 4.09 MB/s
  • Empirical Validation of L4 Domination:
    Under high-concurrency multi-socket stress (k6), cumulative data transfer (red curve) perfectly matches the predicted theoretical aggregate slope of ~54.0 MB/s (dashed black line) due to sender stalling, proving network physics override application efficiency under buffer constraints.
Fig. 9: Cumulative data transfer comparison. Under constrained TCP windows, the empirical transfer slope perfectly overlaps with the 54.0 MB/s theoretical BDP limit.

L4 Throughput Dynamics & TCP ACK Bundling

  • Dynamic Time-Series Dynamics:
    Sustained average bounded to ~54.0 MB/s vs. highly volatile, oscillating instantaneous throughput.
  • Transient Spikes (~100 MiB/s):
    Extreme temporary throughput bursts driven by WAN jitter, intermediate queueing delays, and multi-socket concurrency.
  • TCP ACK Compression & Bundling:
    WAN latency forces ACKs to accumulate in intermediate buffers, hitting the sender in rapid-fire clusters and releasing stalled windows.
  • Coordinated Sender Stalling:
    Immediate post-burst depletion of the constrained 64 KB window triggers synchronized socket stalls awaiting the next ACK cluster.

CAP Theorem Validation via Latency ECDFs

  • Sigmoidal Cumulative Distribution (ECDF):
    The empirical latency profiles exhibit a mathematically canonical sigmoidal (∫) geometry. This exceptionally steep near-vertical transition indicates a near-zero variance, validating highly deterministic performance with negligible network jitter under stationary cloud continuum conditions.
  • The Consistency Penalty (ΔT):
    A rigid, parallel horizontal displacement is observed between the two distributions:
    • Eventual Consistency (AP / BASE): Median latency of 72 ms (optimized local core write at Frankfurt).
    • Strong Consistency (CP / ACID): Median latency of 88 ms (synchronous blocking core + edge write at London).
  • Empirical Proof of Brewer's CAP Theorem:
    The measured delta is exactly:
    ΔT = TCP - TAP = 16 ms
    which correlates precisely with the physical WAN Round-Trip Time (RTT) between London and Frankfurt, demonstrating that synchronous consensus geographic blocks impose a non-negotiable physical transport penalty.

Storage Backend Trade-offs & The Throughput Paradox

  • The Throughput Paradox:
    Under an intense concurrent workload of 500 VUs, S3-based cloud object storage (Spaces) running on the BASE paradigm achieves a 42% reduction in client-perceived average latency (101.15 ms) compared to the highly optimized, local SSD transactional ACID path (176.80 ms).
  • The Physical Root (Eliminating Queue Starvation):
    This paradox is driven by L7 offloading. Writing directly to local SSD forces all traffic synchronously through the core host and NGINX proxy, saturating the block controller and inducing severe kernel queuing delays (Tq). Conversely, Harbor's HTTP 307 Redirect bypasses NGINX entirely, delegating concurrent bulk streaming directly to the highly parallel S3 distributed backend.
  • Converged Transport-Layer Throughput:
    Despite S3's latency advantage, both storage backends converge to an identical aggregate throughput plateau of ≈36.80 MB/s.
  • The Ultimate Leveler:
    Once local host storage bottlenecks are bypassed, geodistributed data transfer remains strictly bounded by Layer 4 transport physics (WAN RTT and Bandwidth-Delay Product constraints).

  • VM Host vs. Container Isolation:
    To resolve telemetric discrepancies, we distinguish the total VM host footprint (~1.5 GB under peak load, including OS kernel, NGINX proxy, and monitoring agents) from the strictly isolated middleware stack peaking at 1085 MB (Harbor) vs. 843 MB (Registry:2).
  • Sustained Compute Scaling Profiles (500 VUs):
    • Harbor (Compute-Bound / Self-Induced Thrashing): Average CPU is low (31.9%) due to S3 data-plane offloading. However, peak stress drives CPU to 100% due to intense kernel scheduler thread contention and PostgreSQL connection starvation.
    • Registry:2 (I/O-Bound / Steady State): Locks the host CPU at a sustained 86.1% (peaking at 100%) in a highly productive steady state, actively proxying and processing every network and disk block transaction.
